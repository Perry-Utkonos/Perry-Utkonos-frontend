# Fate

Приложение знакомств: анкеты, свайпы, взаимные лайки и переписка. Регистрация, профили, лайки и сообщения работают через backend и PostgreSQL; сообщения доставляются через SignalR. В интерфейсе сохранены две темы, карточки, просмотр фотографий и адаптивный макет.

React 18 · TypeScript · Vite · ASP.NET Core · PostgreSQL · SignalR

## Запуск вместе с backend

Нужны Git, Node.js 24 и работающий Docker с Compose v2 и Linux-контейнерами. Выполните из папки с `package.json`:

```sh
node integration/prepare.mjs
docker compose --env-file .tmp/runtime/compose.env -f compose.integration.yaml up --build -d
```

После сборки откройте <http://127.0.0.1:8080> и зарегистрируйтесь. База сначала пустая; для проверки знакомства и переписки нужны два аккаунта. Используйте разные браузеры или обычное и приватное окно.

Скрипт скачивает совместимую версию backend, применяет включённые исправления и создаёт локальные секреты. Данные сохраняются в Docker volumes. Повторный запуск не меняет секреты. Готовая удалённая БД и VPN для этого варианта не используются.

Проверка состояния:

```sh
docker compose --env-file .tmp/runtime/compose.env -f compose.integration.yaml ps
docker compose --env-file .tmp/runtime/compose.env -f compose.integration.yaml logs --tail=100 api web
```

`web` должен стать `healthy`. Остановка с сохранением базы:

```sh
docker compose --env-file .tmp/runtime/compose.env -f compose.integration.yaml down
```

Не добавляйте `-v`, если база нужна. Изменение порта, запуск на сервере и подключение репозитория DevOps описаны в [docs/deployment.md](docs/deployment.md).

## Разработка frontend

Оставьте backend-стек работающим и откройте второй терминал в этой папке:

```sh
npm ci
npm run dev
```

Адрес Vite появится в терминале, обычно <http://127.0.0.1:5173>. Изменения сразу видны в браузере; остановка — `Ctrl+C`. В PowerShell при ошибке `npm.ps1` используйте `npm.cmd`.

Vite передаёт `/api/` и `/hubs/chat` в `http://127.0.0.1:8080`. Другой адрес задаётся через `API_PROXY_TARGET` в `.env`, см. [.env.example](.env.example). Пароль базы и JWT-ключ в переменные `VITE_*` не помещают: они доступны браузеру.

| Команда | Результат |
| --- | --- |
| `npm run build` | Проверка TypeScript и сборка сайта в `dist/`. |
| `npm test` | Проверки API-клиента, обновления токенов и обработки сообщений. |
| `npm run test:integration` | Проверки работающего backend; требуют отдельной тестовой базы, подробности ниже. |

| `src/pages/` | Страницы и формы, список ниже. |
| `src/styles/` | Общие стили, адаптивность и порядок подключения CSS. |
| `src/types/` | Типы данных интерфейса. |
| `public/images/` | Статические изображения, доступные по `/images/имя-файла`. |
| `Dockerfile`, `nginx.conf` | Сборка frontend, раздача страниц и прокси к API/SignalR. |
| `compose.integration.yaml` | Совместный запуск сайта, API, PostgreSQL и Redis. |
| `integration/` | Подготовка backend, его исправления, контракт API и патч DevOps. |
| `tests/` | Автоматические проверки. |
| `design/` | Материалы Figma; инструкция в [design/README.md](design/README.md). |

Стили экранов и компонентов лежат рядом с ними: `.css` — основные правила, `.theme.css` — темы. `src/styles/index.ts` подключает их в порядке «базовые → адаптивность → темы → формы и состояния API». Существующее оформление сохранено.

`package.json` содержит команды и зависимости, `package-lock.json` фиксирует их версии, `vite.config.ts` настраивает сборку и прокси. `node_modules/`, `dist/`, `.tmp/`, `.backups/` и локальные секреты исключены из Git.

## Данные и ограничения

Новая настоящая анкета создаётся регистрацией и заполняется на странице профиля. Сообщения и лайки сохраняются на сервере. Совпадение появляется только после взаимного лайка. При недоступном API интерфейс показывает ошибку и повторную попытку.

Старые примеры оставлены в `src/data/users.ts`, `src/data/chats.ts`, `src/data/chatState.ts` и `src/hooks/useLikes.ts`; приложение их не использует. Для новой **примерной** анкеты добавьте объект в `users` с уникальным `id`, а фотографии положите в `public/images/`. Если нужен начальный пример чата, добавьте запись с тем же `userId` в `chatPreviews` и сообщения под этим ключом в `initialMessages`. Это меняет только сохранённые примеры, а не базу backend.

Пока сервер не предоставляет:

- Загрузку файлов: фото анкеты задаются ссылками или путями `/images/…`.
- Генерацию совместимости и раскладов: отсутствующий результат показывается без выдуманных процентов.
- Приём оплаты и выдачу подписки: создаётся только запись `pending`, деньги не списываются.
- Уведомления, управление приватностью, восстановление пароля и удаление аккаунта. Недоступные настройки отмечены в интерфейсе.

Контракт и исправления backend: [integration/BACKEND.md](integration/BACKEND.md). Изменения backend и DevOps включены как патчи; в командные репозитории они автоматически не отправляются.

## Проверка интеграции

`npm run test:integration` использует настоящий API и создаёт тестовые аккаунты, лайки, сообщения и ожидающий платёж. Запускайте с отдельной тестовой базой. Адрес задаётся переменной `FATE_TEST_API`, например в Git Bash:

```sh
FATE_TEST_API=http://127.0.0.1:8080/api npm run test:integration
```

Проверены сборка frontend и обмен с настоящими backend/PostgreSQL, в том числе через Nginx. Docker в среде разработки отсутствовал, поэтому сборку образов и запуск Compose нужно проверить на машине с Docker.
