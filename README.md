# Fate

Приложение знакомств с анкетами, свайпами, взаимными лайками и чатами. Есть две темы, просмотр фото и адаптация под телефон.

React 18 · TypeScript · Vite · ASP.NET Core · PostgreSQL · SignalR

## Локальный тест без регистрации

Запуск: `npm.cmd run dev:demo` → <http://127.0.0.1:5174>. Регистрация, backend и Docker не нужны.
Тестовые анкеты и чаты; обновление страницы сбрасывает изменения.
Демо работает только локально в режиме разработки. Обычный запуск и сборка требуют входа.

## Запуск вместе с backend

Нужны Git, Node.js 24 и работающий Docker с Compose v2 и Linux-контейнерами. Выполните из папки с `package.json`:

```sh
node integration/prepare.mjs
docker compose --env-file .tmp/runtime/compose.env -f compose.integration.yaml up --build -d
```

После сборки откройте <http://127.0.0.1:8080> и зарегистрируйтесь. База сначала пустая; для проверки знакомства и переписки нужны два аккаунта. Используйте разные браузеры или обычное и приватное окно.

Скрипт скачивает совместимую версию backend, применяет включённые исправления и создаёт локальные секреты. Данные сохраняются в Docker volumes. Повторный запуск не меняет секреты. Готовая удалённая БД и VPN для этого варианта не используются.

Проверка состояния:

```sh
docker compose --env-file .tmp/runtime/compose.env -f compose.integration.yaml ps
docker compose --env-file .tmp/runtime/compose.env -f compose.integration.yaml logs --tail=100 api web
```

`web` должен стать `healthy`. Остановка с сохранением базы:

```sh
docker compose --env-file .tmp/runtime/compose.env -f compose.integration.yaml down
```

Не добавляйте `-v`, если база нужна. Изменение порта, запуск на сервере и подключение репозитория DevOps описаны в [docs/deployment.md](docs/deployment.md).

## Разработка frontend

Оставьте backend-стек работающим и откройте второй терминал в этой папке. В Windows PowerShell используйте `npm.cmd`: так команды работают и при запрете выполнения `npm.ps1`.

```powershell
npm.cmd ci
npm.cmd run dev
```

В Git Bash, Linux и macOS используйте `npm` вместо `npm.cmd` во всех командах ниже. Менять политику выполнения PowerShell не требуется.

Адрес Vite появится в терминале, обычно <http://127.0.0.1:5173>. Изменения сразу видны в браузере; остановка — `Ctrl+C`.

Vite передаёт `/api/` и `/hubs/chat` в `http://127.0.0.1:8080`. Другой адрес задаётся через `API_PROXY_TARGET` в `.env`, см. [.env.example](.env.example). Пароль базы и JWT-ключ в переменные `VITE_*` не помещают: они доступны браузеру.

| Команда в PowerShell | Результат |
| --- | --- |
| `npm.cmd run build` | Проверка TypeScript и сборка сайта в `dist/`. |
| `npm.cmd test` | Проверки API-клиента, обновления токенов и обработки сообщений. |
| `npm.cmd run test:integration` | Проверки работающего backend; требуют отдельной тестовой базы, подробности ниже. |

## Где что лежит

| Путь | Назначение |
| --- | --- |
| `src/main.tsx` | Вход в React, роутер и подключение стилей. |
| `src/App.tsx` | Авторизация, общие данные, лайки и совпадения. |
| `src/AppRoutes.tsx` | Маршруты и загрузка анкеты по ID. |
| `src/layouts/AppLayout.tsx` | Общий макет, навигация и окно совпадения. |
| `src/api/client.ts` | HTTP-запросы, JWT, обновление токенов, ошибки и сессия текущей вкладки. |
| `src/api/contracts.ts` | Типы запросов и ответов backend. |
| `src/api/profiles.ts` | Преобразование серверной анкеты в данные интерфейса. |
| `src/auth/AuthContext.tsx` | Текущий аккаунт, своя анкета и выход. |
| `src/hooks/usePeople.ts` | Анкеты, сохранённые лайки и рекомендации сервера. |
| `src/hooks/useChats.ts` | SignalR, список чатов, история и восстановление после обрыва связи. |
| `src/hooks/chatMessages.ts` | Объединение сообщений без дублей и догрузка пропущенной истории. |
| `src/hooks/useTheme.ts`, `src/theme.ts` | Выбор и сохранение темы. |
| `src/components/` | Карточка со свайпами, навигация и другие элементы. |
| `src/pages/` | Страницы и формы, список ниже. |
| `src/styles/` | Общие стили, адаптивность и порядок подключения CSS. |
| `src/types/` | Типы данных интерфейса. |
| `public/images/` | Статические изображения, доступные по `/images/имя-файла`. |
| `Dockerfile`, `nginx.conf` | Сборка frontend, раздача страниц и прокси к API/SignalR. |
| `compose.integration.yaml` | Совместный запуск сайта, API, PostgreSQL и Redis. |
| `integration/` | Подготовка backend, его исправления, контракт API и патч DevOps. |
| `tests/` | Автоматические проверки. |
| `design/` | Материалы Figma; инструкция в [design/README.md](design/README.md). |

Стили лежат рядом с компонентами: `.css` — основные правила, `.theme.css` — темы. Порядок подключения задаётся в `src/styles/index.ts`. Общие шрифты и размеры текста — в `src/styles/typography.css`.

`package.json` содержит команды и зависимости, `package-lock.json` фиксирует их версии, `vite.config.ts` настраивает сборку и прокси. `node_modules/`, `dist/`, `.tmp/`, `.backups/` и локальные секреты исключены из Git.

## Страницы

| Файл в `src/pages/` | Адрес | Назначение |
| --- | --- | --- |
| `AuthPage.tsx` | Любой адрес до входа | Вход и регистрация. |
| `FeedPage.tsx` | `/` | Анкеты и свайпы. |
| `UserProfilePage.tsx` | `/profile/:id` | Чужая анкета и фотографии. |
| `ChatsPage.tsx` | `/chats` | Список диалогов и начало разговора. |
| `ChatPage.tsx` | `/chat/:id` | Сообщения, история, статусы прочтения и набора текста. |
| `CompatibilityPage.tsx` | `/compatibility/:id` | Совместимость, если сервер вернул расчёт. |
| `ProfilePage.tsx` | `/me` | Своя анкета, редактирование и выход. |
| `SettingsPage.tsx` | `/settings` | Выбор темы и доступные настройки. |
| `SubscriptionPage.tsx` | `/subscription` | Информация о подписке и ожидающие платежи. |

`:id` — UUID анкеты или диалога из API. Для новой страницы добавьте маршрут в `AppRoutes.tsx`; загрузчики страниц по требованию лежат в `routeLoaders.ts`.

## Данные и ограничения

После регистрации анкету можно заполнить в профиле. Сообщения и лайки сохраняются на сервере. Совпадение появляется только после взаимного лайка. Если API недоступен, появится ошибка и кнопка повторной попытки.

Пока сервер не предоставляет:

- Загрузку файлов: фото анкеты задаются ссылками или путями `/images/…`.
- Автоматический расчёт совместимости и расклады.
- Приём оплаты и выдачу подписки: создаётся только запись `pending`, деньги не списываются.
- Уведомления, управление приватностью, восстановление пароля и удаление аккаунта. Недоступные настройки отмечены в интерфейсе.

Контракт API описан в [integration/BACKEND.md](integration/BACKEND.md). Патчи backend и DevOps лежат в `integration/`.

## Проверка интеграции

`npm run test:integration` обращается к API и создаёт тестовые аккаунты, лайки, сообщения и заявку на оплату. Запускайте с отдельной тестовой базой. Адрес задаётся переменной `FATE_TEST_API`, например в Git Bash:

```sh
FATE_TEST_API=http://127.0.0.1:8080/api npm run test:integration
```

Сборку Docker-образов и запуск Compose ещё нужно проверить.
