# Скрипты дизайна Fate

`design/` хранит исходники импорта в Figma и исторический снимок состояния макета. Для запуска React-приложения эта папка не нужна.

## Подготовка из корня проекта

```powershell
npm ci
npm run design:prepare
```

Команда сначала извлекает иконки из установленного Lucide, затем собирает два файла:

- `figma-import.generated.js` — тело одной асинхронной функции для среды Figma Plugin API, например инструмента исполнения кода внутри Figma. Это не самостоятельный Node.js-скрипт.
- `code.generated.js` — тот же импорт с обёрткой для локального development plugin. Результат выводится в консоль плагина; уведомление показывает `created` или `unchanged`.

Оба результата исключены из Git: их нужно заново подготовить после изменения исходников, цветов, иконок или конфигурации.

## Где запускать

1. Откройте Figma Design **в файле, указанном в `figma-state.json`**. Создайте в нём новую пустую страницу. Уже существующий макет сохраните для сравнения.
2. В Figma Desktop создайте локальный development plugin через меню разработки плагинов. Figma выдаст ему свой `id`.
3. Скопируйте `manifest.template.json` в `design/manifest.json` и подставьте выданный `id` вместо `REPLACE_WITH_YOUR_DEVELOPMENT_PLUGIN_ID`. Импортируйте этот `manifest.json` как development plugin. Он запускает лежащий рядом `code.generated.js`.
4. Запустите плагин на подготовленной странице. Должны появиться секция экранов, библиотека компонентов, коллекция переменных с темами Purple/Cream и текстовые стили.

Шаблон использует `documentAccess: dynamic-page`, асинхронное применение текстовых стилей и `enablePrivatePluginApi`, чтобы локальный плагин мог проверить `figma.fileKey`. Доступ к сети отключён; изображения должны уже существовать в нужном файле. Параметры описаны в официальной [документации manifest](https://developers.figma.com/docs/plugins/manifest/); ограничение `fileKey` — в [документации figma](https://developers.figma.com/docs/plugins/api/figma/).

Для среды, принимающей асинхронное тело функции, передавайте **целиком** `figma-import.generated.js`. Запускать исходные фрагменты по отдельности не следует: они используют общую область видимости и общий обработчик ошибок.

## Порядок и общие переменные

| Этап | Источник | Что готовит или использует |
| --- | --- | --- |
| 1 | `prepare-icons.mjs` | Извлекает SVG из Lucide в `icons.json`. Запускается в Node.js из корня проекта. |
| 2 | `build-import.mjs` | Читает `icons.json`, `figma-state.json`, CSS-переменные тем и исходники. Встраивает `ICONS`, `COLORS`, `CONFIG` и вычисляет отпечаток версии. |
| 3 | `figma-bootstrap.js` | Проверяет файл, повторный запуск, наличие изображения и шрифтов. Создаёт `page`, `board`, `V` (переменные), `S` (ID текстовых стилей), `STYLE_CONFIG`, `made`, `tracked`, `createdResources`, `oldStartingPoints`. Открывает общий `try`. |
| 4 | `figma-helpers.js` | Функции `A`, `T`, `Icon`, `Photo`, `Rule`, `Props`, `Chip`, `Button`, `Card`, `Spacer`, `Header`, `Nav`, `Screen`, `End`, `paint`, `radius`, `instance`. Используют объекты из предыдущих этапов. |
| 5 | `figma-components.js` | Создаёт `shelf` и `componentsByName`, компоненты кнопок, чипов, навигации, строки чата и совместимости. |
| 6 | `figma-screens.js` | Собирает экраны, применяет текстовые стили, связывает прототип и навигацию, сохраняет метку версии и результат. Закрывает общий `try/catch`. |

Импорт сам создаёт свою коллекцию переменных и стили; ему больше не нужны предварительно созданные переменные с определёнными именами. Компоненты находятся через `componentsByName` текущего запуска, поэтому чужой компонент с таким же именем не будет случайно использован.

## Повторные запуски и ошибки

- Если на текущей странице уже есть результат **этой же версии**, импорт возвращает `unchanged`, не создавая узлы, стили или переменные.
- Если на странице есть другая версия либо старый макет без метки версии, импорт останавливается до изменений. Для новой версии используйте новую пустую страницу в том же файле.
- В новом запуске создаётся отдельная коллекция переменных и стили. Импорт в разные страницы намеренно создаёт отдельные версии; это не обновление существующей библиотеки.
- Ошибки после начала сборки запускают удаление только узлов, переменных и стилей, созданных этим запуском. Старые точки старта прототипа восстанавливаются. Старые макеты не удаляются.
- Новая точка старта добавляется к существующим, а не заменяет их.

`npm test` проверяет защиту от одинакового запуска, другой версии, неверного файла, старого немаркированного макета и отсутствующей фотографии. Эти проверки выполняются с минимальной имитацией API и не заменяют запуск в Figma. Откат и полную сборку узлов нужно проверять в самом редакторе.

## Что зависит от figma-state.json

`fileKey` проверяет целевой файл, а `portrait` задаёт уже импортированное изображение. Если его нет, скрипт останавливается до создания узлов. Хэш изображения действителен в контексте Figma-файла; локальный путь к JPG сам по себе его не заменяет.

Поля `board`, `section`, `components`, `screens`, `capture`, `page`, `pending` описывают **предыдущую версию макета**. Новый импорт не ищет узлы по этим ID, не изменяет их и не перезаписывает снимок автоматически. Актуальные ID нового запуска возвращаются в результате и сохраняются в plugin data секции. После реальной проверки их можно вручную перенести в снимок состояния.

## Соответствие приложению

| Область | Что согласовано | Что отличается |
| --- | --- | --- |
| Цвета | Новый импорт читает обе темы из `src/styles/global.css`, включая цвет текста на кнопках; SVG-иконки привязаны к переменным. | Старый онлайн-макет автоматически не обновляется. Некоторые декоративные градиенты в экранах заданы отдельно. |
| Шрифты | Manrope и DM Sans совпадают с приложением; создаются и применяются текстовые стили. | Размеры описывают концепт и не воспроизводят каждый CSS-селектор. |
| Компоненты | Базовая кнопка 48 px, строка чата 82 px и аватар 49 px согласованы с CSS; нижняя навигация содержит четыре пункта, включая настройки, и её переходы связаны. | Figma-компоненты не заменяют React-компоненты и не связаны через Code Connect. Часть фирменных изображений заменена символами. |
| Макет | Мобильные экраны 390 × 844 и десктопный концепт 1440 × 900. | Сайт адаптивный; десктопный макет в Figma содержит дополнительные панели. Это не точная копия текущей вёрстки. |
| Сценарии | Основные переходы между анкетой, чатами, профилем, совместимостью, подпиской и настройками. | Поиск, фильтры, редактор профиля и часть пояснений подписки — предложения дизайна. Реальная оплата и успешное оформление не реализованы. |
| Фото | Используется существующий портрет из состояния; для других собеседников предусмотрены инициалы. | Полная фотогалерея сайта не импортируется и внешние фото не загружаются. |

Интервал тела мобильных экранов ограничен 18 px вместо прежних 20 px, чтобы уменьшить переполнение. Фактические границы и переносы необходимо проверить в Figma: изменение шрифтов и текста влияет на высоту.

`UI-UX-handoff.md` и `figma-state.json` содержат историю старого макета. В этой ревизии выполнены локальная подготовка, синтаксическая проверка и проверки отказов до изменения документа. Полный новый импорт в Figma и визуальное сравнение с сайтом пока не выполнены.
